# 節目類型自動正規化設計規格

**日期：** 2026-08-08
**分支：** main
**影響範圍：** `scripts/genre_rules.py`（新增）、`scripts/convert_excel.py`

---

## 背景與目標

爬蟲從粉專貼文抓下來的「類型」欄是自由文字，同一個概念有大量寫法。週榜與日榜合計 19,147 列裡出現 45 種寫法，其中 1,597 列（8.3%）不屬於 `src/types/index.ts` 定義的九種合法 `Genre`。

後果有二：

1. 非法值直接寫進 `rankings.json`，前端 `GENRE_COLORS[genre]` 查不到顏色
2. 目前靠人工在 Excel 裡逐格改，改不完也不會停

爬蟲端既有的 `normalize_genre()` 只做**格式**清理（去 `[在榜N周]`、全形括號轉半形、括號前補空格），不做**詞彙**對應，所以 `台綜`、`實境 (韓)`、`紀實 (美)` 原樣寫進 Excel。

**目標：** 轉檔時自動把錯誤／變體寫法修正成合法類型，同時保留辨識新類型的能力 —— 沒見過的寫法必須安全落到「其他」並主動浮上來，不能被硬塞進九類，也不能悄悄消失。

---

## 設計決策

四個已確認的決定，以及理由：

| 決定 | 選擇 | 理由 |
|---|---|---|
| 沒收錄的新類型怎麼處理 | 歸「其他」＋列入待審清單 | 圖表不會壞，且不漏掉任何新東西；升格與否由人決定 |
| 修正發生在哪一層 | 只改 JSON，Excel 保持原樣 | 規則一改，16,000 筆歷史資料立刻全部適用；不動手維護的檔案；`實境 (韓)` 的國別資訊不會遺失 |
| 要不要有手工對照表 | **不要** | 只有結構規則能自動修正；規則涵蓋不到的一律進待審，不存在看不見的硬編碼對應 |
| 審核結果記在哪 | 程式內的 `REVIEWED` 清單 | 待審清單能收斂到零，下次只提示真正沒見過的寫法 |

## 架構

新增 `scripts/genre_rules.py`：純函式、無 I/O、無模組級可變狀態。

```python
canonicalize(raw: str | None) -> tuple[str, str]
# 回傳 (合法類型, 判定依據)
# 判定依據：'canon' | 規則名 | 'reviewed' | 'pending'
```

統計由呼叫端（`convert_excel.py`）累積，規則層保持純函式。

拆成獨立模組的理由：`convert_excel.py` 已逾 900 行，類型判定是自成一格的邏輯，獨立後才能單獨測試與理解。

### 模組常數

| 常數 | 內容 | 何時修改 |
|---|---|---|
| `CANONICAL_GENRES` | 目前九類，須與 `src/types/index.ts` 的 `Genre` 一致 | 升格新類型時 |
| `REVIEWED` | 已審核、確認維持「其他」的原始寫法 | 看完待審清單後 |
| 規則常數 | `NON_DRAMA`、`ANIME`、`COUNTRY` 等 | 極少 |

**`REVIEWED` 不影響分類結果**，只控制要不要再提示。這是它與對照表的本質差別：對照表改變輸出，`REVIEWED` 只改變提示。初版留空，第一次執行即產生第一份待審清單。

## 處理流程

```
clean(raw)  →  結構規則  →  未命中：'其他' + pending
```

### 第一層：清理

依序執行：

1. 全形括號 `（）` → 半形 `()`
2. 去除 `[...]`／`【...】` 尾注及其後文字（`[在榜N周]`）
3. 去除 `／` 或 `/` 後接數字的尾注（`韓劇 /706萬小時`）
4. 去除尾端標點 `。、,，.`（`英劇。`）
5. 補平不對稱右括號（`韓劇)`）
6. 括號前正規化為恰好一個空格

清理後若已屬 `CANONICAL_GENRES`，回傳 `'canon'`。

### 第二層：結構規則

按序比對。先把字串拆成 `base` 與括號內的 `loc`（`實境 (韓)` → base=`實境`, loc=`韓`）。

| 條件 | 結果 | 依據名 |
|---|---|---|
| `base ∈ {紀實, 直播, 音樂體驗, 電影, 新聞}` | 其他 | `非戲劇類` |
| `base ∈ {動畫, 動畫劇, 動漫, 動畫短劇}` 且 `loc ∈ {None, 日}` | 動畫劇 (日) | `動畫-日` |
| `base ∈ {動畫, 動畫劇, 動漫, 動畫短劇}` 且 loc 為其他地區 | 其他 | `動畫-非日` |
| `base == 實境` | 實境秀 | `實境` |
| `base` 符合 `[韓台日美陸中英]綜` | 實境秀 | `綜藝` |
| `base` 符合 `[韓美陸中日台英]` ＋ 可選「劇」 | 對應國別 | `國別縮寫` |
| `base` 符合 `[韓美陸中日台英]&…` | 主國別 | `合製-主國別` |

國別對應：韓→韓劇、美→美劇、陸→陸劇、中→陸劇、日→日劇、台→台劇、英→英劇。

規則看**結構**而非死記字串，因此能推廣到未見過的寫法：以後出現 `實境 (泰)`、`動漫 (韓)` 不需修改任何程式碼即自動歸位。

### 第三層：未命中

回傳 `('其他', 'reviewed')` 若清理後的值在 `REVIEWED` 中，否則 `('其他', 'pending')`。

兩者分類結果相同，差別僅在是否列入報告。

### 邊界情況

- `raw` 為 `None` 或空字串 → `('其他', 'canon')`
- `raw` 非字串（數字等）→ 先 `str()` 再處理

## 升格流程

當某個待審類型累積到值得成為正式類別（例如泰劇 97 列），需依序修改三處。此步驟寫成 `genre_rules.py` 檔頭註解：

1. `src/types/index.ts` — 加入 `Genre` union
2. `src/constants/genres.ts` — 加入 `GENRE_COLORS` 與 `GENRE_LABELS`
3. `scripts/genre_rules.py` — 加入 `CANONICAL_GENRES`

**配色限制：** 依 `CLAUDE.md`，`GENRE_COLORS` 前八色是 OKLab 驗證過的色盲可辨色階，第九位「其他」為中性灰。新增第十個類型需重新驗證整組配色的相鄰可辨性與對紙白底 ≥ 3:1 對比，不是加一個 hex 就好。升格是有成本的決定 —— 這正是待審清單存在的價值。
