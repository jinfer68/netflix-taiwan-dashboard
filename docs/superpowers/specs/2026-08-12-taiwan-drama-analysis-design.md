# 台劇分析頁：片名實體正規化與走勢圖重構設計規格

**日期：** 2026-08-12
**分支：** fix/daily-score-and-genre-normalization
**影響範圍：** `scripts/convert_excel.py`、`src/types/index.ts`、`src/components/charts/TaiwanDramaChart.tsx`、`src/components/charts/RankTrendChart.tsx`

---

## 背景

台劇分析頁目前有兩個相互糾纏的問題：榜單上片名重複、標記不清；走勢圖的線畫得不對。追查後確認兩者都不是排版問題，而是資料層的錯誤透過圖表暴露出來。

### 問題 1：同一個節目被拆成多筆

`taiwanDramaRankings` 共 97 筆，其中至少五類是同一實體的重複列：

| 類型 | 實例 |
|---|---|
| 全形／半形空格不一致 | `嗨！營業中` vs `嗨！ 營業中`；`來吧！營業中2：星之沙龍` vs `來吧！營業中2： 星之沙龍` vs `來吧！營業中 2：星之沙龍` |
| 片名黏到髒前綴 | `獨來吧！營業中`、`獨痞子英雄`（僅出現在週榜來源表，無日榜資料） |
| 片名尾字差異 | `光露營就很忙了` vs `光露營就很忙` |
| 季別標示缺漏或寫法不一致 | `華燈初上` 與 `華燈初上 S1/S2/S3` 並存；`最佳利益` 與 S2/S3；`嗨！營業中` 與 S3–S7；`我的婆婆怎麼那麼可愛2` |
| 屬性表 key 與榜單 title 不一致 | 屬性表寫 `誰是被害者 第1季`，榜單寫 `誰是被害者 S1` |
| 實境綜藝混入台劇榜 | 營業中系列、星廚之戰、全明星出發吧！、交換情侶等 |

倒數第二類造成 `TaiwanDramaChart` 的 `showAttributes[d.title]` 靜默失敗：tooltip 的集數與上架週數為空，`releaseWeeks` 退回預設值 1，覆蓋率因此可能算出超過 100%。`SPECIAL_NOTES` 的兩個 key 也是舊寫法，該註記從未顯示過。

### 問題 2：`dayIndex` 錨點錯誤

來源 Excel「Clean Data - 台劇每日排名」的「上線天數」欄，2145 筆中有 **915 筆（43%）為負值**。錨點被設在最近一次回鍋上榜，而非首播：

- `村裡來了個暴走女外科` 實際 2022-05-09 上榜（標為第 −535 天），「第 1 天」錨在 2023-10-27
- `有生之年` 首播檔期 2023-09-17（標為第 −353 天起），金鐘獎回鍋的 2024-10-21 被錨為第 1 天

「劇集屬性資料庫」沒有上架日期欄位，因此無法用真實上架日修正，只能從榜單資料自行重錨。

### 問題 3：走勢圖渲染

- `XAxis` 未指定 `type="number"`（`RankTrendChart.tsx:158`），`dayIndex` 被當類別軸繪製，−399 與 1 之間的跳空被畫成等距一格，斜率完全失真
- `type="monotone"` 對離散名次做平滑插值，會在轉折處過衝畫出不存在的中間值
- 29 個節目的 dayIndex 不連續（如 `影后` 為 1–53、55–59、66），配合 `connectNulls={false}` 造成線斷成數截、留下孤立的點
- EP 參考線畫在 `dayIndex = 0, 7, 14…`，但資料的 dayIndex 從 1 起算，已存在一格偏移。`DailyRankingEntry` 的註解寫「0 起算」也與實際不符

---

## 決策摘要

| 議題 | 決策 |
|---|---|
| 「一部劇」的定義 | 修正變體寫法使其合併；季別各自獨立為不同實體 |
| 實境綜藝 | 保留在榜內，只加文字標記，不加篩選器 |
| 榜單長度 | 預設 Top 20，提供「顯示全部」展開 |
| 走勢圖 X 軸 | 以該劇首次上榜日重新錨定為第 1 天 |
| 修正落點 | 全部在 Python 轉換層；前端只負責呈現 |
| 回鍋上榜 | 資料層切分檔期段，走勢圖只畫主檔期，回鍋段以註記呈現 |
| 無季數資料的歸屬 | 以查證過的實際上架日建表指定，不做自動推斷 |

## 資料層設計（`scripts/convert_excel.py`）

處理順序不可調換：**片名正規化 → 季別歸屬 → 檔期段切分與 dayIndex 重錨**。季別歸屬必須在切段之前，因為季界本身就是檔期界；切段必須在正規化之後，因為變體合併會改變一部劇的上榜日集合。

### 1. 片名正規化：擴充 `clean_title`

在現有實作（`convert_excel.py:131`）上追加，順序如下：

1. 全形空格轉半形，壓縮連續空白
2. 移除中文標點前後的空白：`來吧！營業中2： 星之沙龍` → `來吧！營業中2：星之沙龍`
3. 移除中文字與阿拉伯數字之間的空白：`來吧！營業中 2：星之沙龍` → `來吧！營業中2：星之沙龍`
4. 移除「獨」髒前綴。**限定套用在週榜來源表**，因為 `獨痞子英雄`、`獨來吧！營業中` 都沒有日榜資料，此問題是週榜表獨有的。且必須以既有片名為白名單比對（去前綴後存在於已知片名集合才替換），避免誤傷本來就以「獨」開頭的片名
5. 季別寫法統一為 ` SN`：`第3季`、`第三季`、結尾裸數字（`我的婆婆怎麼那麼可愛2` → `我的婆婆怎麼那麼可愛 S2`）一律轉換
6. `TITLE_MAP` 別名表最後套用，新增一筆：`光露營就很忙` → `光露營就很忙了`

**`clean_title` 必須同時套用在「劇集屬性資料庫」的 key 上**，這是修好屬性查表靜默失敗的關鍵。

### 2. 季別歸屬：`SEASON_OVERRIDES`

無季數的日榜資料無法由資料本身可靠推斷季別（詳見下方三個 IP 的證據），因此以查證過的實際上架日建立日期區間對照表。表以 `(正規化後片名, 起始日, 結束日) → 正規化後的目標片名` 為鍵，比對日榜列的日期。

| 原片名 | 期間 | 歸屬 | 依據 |
|---|---|---|---|
| 華燈初上 | 2022-01-07 ~ 02-13 | `華燈初上 S2` | Netflix 分三部上架：第一部 2021-11-26、第二部 2021-12-30、第三部 2022-03-18。此段落在第二部上架後、第三部之前 |
| 華燈初上 | 2022-03-18 ~ 04-09 | `華燈初上 S3` | 起點正是第三部上架日，且上架首日起連續 8 天第 1 名 |
| 最佳利益 | 2023-05-23 ~ 05-30 | `最佳利益 S2` | 最佳利益2 於 2023-05-01 上 Netflix；週榜 S2 落在 2023-05-22 ~ 05-28 |
| 最佳利益 | 2023-06-25 ~ 07-11 | `最佳利益 S3` | 最佳利益3 於 2023-06-03 公視首播；週榜 S3 落在 2023-06-19 ~ 07-09 |
| 嗨！營業中<br>（含全形空格變體） | 2022-10-02 ~ 2023-02-05 | `嗨！營業中 S1` | S1 播映期 2022-10-01 ~ 2023-01-28 |
| 嗨！營業中 | 2023-06-25 ~ 07-23 | `嗨！營業中 S2` | S2 播映期 2023-05-20 ~ 2023-09-02 |

只有一個檔期段、且無同 IP 帶季數兄弟列的節目（如 `影后`），片名維持原樣，**不加 S1 後綴**。

`最佳利益` 是這張表存在的理由：它的兩個季別區間之間只隔 25 天（05-30 → 06-25），低於 30 天的檔期門檻，自動切段會把兩季併成一段。同理，季別歸屬不能以「第 N 段歸第 N 季」的序數規則實作。

轉換時若出現新的無季數資料落在表外，由第 6 節的對帳檢查輸出警告，不靜默歸類。

### 3. 檔期段切分

以「連續兩個上榜日相隔天數」定義檔期邊界。實測分布呈雙峰：

```
1天 ×1917   2天 ×49   …   21天 ×2   26天 ×2   28天 ×1
────────────── 無資料空帶 ──────────────
33天 ×1   35天 ×1   38天 ×1   55天 ×1   56天 ×1   140天 ×1   353天 ×1   486天 ×1
```

28 天與 33 天之間沒有任何資料，**門檻取 30 天**落在空帶中央。

規則：同一片名（**已完成正規化與季別歸屬後**）的上榜日排序後，相鄰間隔 ≥ 30 天即切為新檔期段。主要被切開的節目：

| 節目 | 主檔期 | 後續段 |
|---|---|---|
| 村裡來了個暴走女外科 | 2022-05-09 ~ 06-25（48 天） | 2023-10-24 ~ 10-27（4 天） |
| 有生之年 | 2023-09-17 ~ 11-03（48 天） | 2024-10-21 ~ 10-25（5 天） |
| 美食無間 | 2023-11-04 ~ 11-18（11 天） | 2024-01-13（1 天） |
| 光露營就很忙了 | 2023-04-17 ~ 04-21（5 天） | 2023-05-29 ~ 05-30（2 天） |

`嗨！營業中` 與 `華燈初上` 原本的多段在季別歸屬後已分屬不同片名，不再由此規則處理。

### 4. `dayIndex` 重錨

忽略 Excel 的「上線天數」欄，改以檔期段為單位重算：

```
dayIndex = (該列日期 − 該檔期段最早日期).days + 1
```

主檔期（第 1 段）的 dayIndex 從 1 起算。所有負值消失。

### 5. 綜藝標記

屬性表僅 34 筆、不涵蓋綜藝，因此以片名規則清單判定，產出布林欄位 `isVariety`。初始清單：營業中系列、光開門就很忙了、光露營就很忙了、星廚之戰、全明星出發吧！、交換情侶、來吧！哪裡怕、我們這一攤。

此欄位僅供顯示標記，不影響排序或篩選。

### 6. 對帳檢查

轉換結束前新增兩項驗證，任一不通過即輸出警告清單（不中斷轉換）：

1. 每個出現在 `taiwanDramaRankings` 的 title 都必須能在 `showAttributes` 找到
2. 每筆無季數、且同 IP 存在帶季數兄弟列的日榜資料，都必須被 `SEASON_OVERRIDES` 涵蓋

第 1 項若在本次修正前執行，就會直接指出 `誰是被害者 S1` 對不上 `誰是被害者 第1季`。

## JSON schema 變更（`src/types/index.ts`）

```typescript
export interface DailyRankingEntry {
  dayIndex: number   // 該檔期段的第 N 天（1 起算）
  title: string
  rank: number
  score: number
  runIndex: number   // 檔期段序號，0 = 主檔期
}

export interface ShowAttributes {
  isNetflixOriginal: boolean
  releaseType: 'weekly' | 'allAtOnce' | 'split'
  releaseWeeks: number
  totalEpisodes: string
  isVariety?: boolean
  runs?: ShowRun[]        // 檔期段清單，僅有多段時輸出
}

export interface ShowRun {
  startDate: string       // "YYYY-MM-DD"
  endDate: string         // "YYYY-MM-DD"
  days: number            // 上榜天數
  peakRank: number        // 該段最佳名次
}
```

`DailyRankingEntry` 原註解「0 起算」與實際不符，一併更正。

## 前端：台劇積分榜（`TaiwanDramaChart.tsx`）

1. **預設只畫 Top 20**，圖表下方一行 `顯示全部 N 部 →`（`SEGMENT_BTN` 樣式）切換展開。展開狀態為元件內部 `useState`，不上提到 `App.tsx`
2. **綜藝標記**：Y 軸片名第二行的資訊列（現為 `上架方式 · 集數 · N→M週`）前面加 `綜藝` 字樣，`INK_MUTED` 10px。不配色，避免與上架方式的三色系統打架
3. **修正 `SPECIAL_NOTES` 的 key**，改用正規化後的片名
4. **覆蓋率的缺值處理**：`releaseWeeks` 缺失時顯示 `—`，不再退回預設值 1 硬算出可能超過 100% 的比率
5. **回鍋標記**：有多個檔期段的節目，片名後保留 `※`，tooltip 底部列出各回鍋段的日期與最佳名次

## 前端：走勢圖（`RankTrendChart.tsx`）

1. **`XAxis` 補上 `type="number"`**、`domain={[1, maxDay]}`、`allowDecimals={false}`。跳空自此按比例繪製
2. **`type="monotone"` 改為 `linear`**。名次是離散整數，平滑插值會畫出不存在的中間值
3. **只畫主檔期**（`runIndex === 0`）。`有生之年` 的 X 軸從 355 天縮回 48 天，前段細節完整保留，且不需要斷軸
4. **回鍋段以註記呈現**，不畫進圖裡：圖右上角一行 `※ 有生之年 2024-10 回鍋 5 天，最佳第 7 名`，`INK_MUTED` 11px
5. **檔期段內的缺口**（如 `影后` 的第 54、60–65 天）維持 `connectNulls={false}` 斷開，但在缺口區間補一段同色淡虛線橋接（`strokeDasharray="3 3"`、`strokeOpacity` 0.35），讓人看得出是同一條線而非兩部劇
6. **EP 參考線改為 `1, 8, 15, 22…`**，對齊 1 起算的 dayIndex

## 不做的事

- 不加 brush 或斷軸（broken axis）互動。切檔期已經解決軸被拉長的問題，再加互動是多餘的複雜度
- 不做綜藝／戲劇篩選器。已決定只加視覺標記
- 不合併季別到 IP 層。季別維持各自獨立
- 不新增圖表元件。所有改動都在既有的兩個元件內
- 不嘗試自動推斷季別。證據顯示這在現有資料下不可靠

## 風險與已知取捨

- **重跑轉換會改動 `rankings.json` 這個進版控的產物**，diff 會很大。需確認除了本規格列出的預期變更外，沒有其他非預期差異
- **`華燈初上` 2022-01-07 ~ 02-13 這段可能混雜第一部與第二部的名次**。第一部 2021-11-26 上架，在該期間仍留在週榜上（週榜 S1 有 7 週紀錄），但日榜來源每天只記錄一筆 `華燈初上`，無法分辨。歸為 S2 是就現有資料最合理的判讀，非確證
- **`SEASON_OVERRIDES` 是人工維護的表**。新的無季數資料靠對帳檢查提醒，不會自動歸類
- **「獨」前綴的移除依賴白名單比對**。若未來出現新的髒前綴，規則不會自動涵蓋，需靠對帳檢查發現
- **綜藝判定是片名規則清單**，不是資料欄位。新節目上榜時可能漏標，屬於可接受的維護成本
- **只畫主檔期會隱藏回鍋段的曲線形狀**。這是「不要拉長軸」的直接代價，以文字註記補償
